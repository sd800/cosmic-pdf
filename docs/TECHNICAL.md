# Cosmic PDF technical reference

Security policy, trust boundaries, injection defenses, and vulnerability reporting are maintained in [SECURITY.md](SECURITY.md). This reference covers implementation and interaction details.

## Authority and ownership

The project follows Cosmic Gemini's Central → Province → Product separation. `background/central.js` routes events, never parses documents. Standing Province owns automatic opening and per-tab native-reader exemptions. Operations Province owns extension administration and serialized preference writes. Customs Province owns the privileged AI explanation product as well as the document workspace boundary. The reader/renderer/OCR workspace is the Customs boundary: it handles imported bytes but cannot invoke sibling products. The host exposes a small explicit command bridge, not arbitrary RPC. The three province names describe ownership, not a reason to add empty lifecycle machinery.

Preferences are normalized against a whitelist in `core/settings.js`. Unknown/deprecated fields are ignored, never migrated. Defaults are automatic appearance, 100% initial zoom, 4× sampling, sharpening off and on-request English/Simplified Chinese OCR. Interface languages are en-US/zh-CN. Recognition languages additionally include Traditional Chinese. Open readers snapshot rendering quality and OCR language/detail settings; subsequent opens/reloads use changed settings. Appearance controls change the current reader only. All toolbar modes use one sun/moon button, with a stable switch-light/dark tooltip. Single-click initially toggles the saved default or its opposite; after a menu choice it flips the current displayed mode. The reader-local Auto/Light/Dark menu supports an explicit system-following override. Changing toolbar layout leaves the override unchanged. Toolbar visibility changes synchronize to open readers without reparsing their PDFs; rendering quality and OCR language/detail preferences remain snapshots. Interface language, document-date format, Find shortcut preference and OCR button behavior update immediately without reparsing or restarting recognition.

## PDF takeover and return

Chrome 128+ response-header declarativeNetRequest rules redirect GET PDF responses in `main_frame`, `sub_frame` and `object` requests to the extension-owned host. This covers normal iframe/embed/object PDF loading without a content script, webpage mutation observer or additional API permission. A higher-priority allow rule preserves attachment downloads. HTML named `.pdf` does not match unless its MIME type is PDF; generic binary data requires a PDF suffix. POST bodies and site blob URLs are not intercepted. Local PDF opening uses the existing tabs URL-change event because Chrome does not reliably apply network redirect rules to file navigation. It requires the extension enabled and Chrome's explicit file-access grant, checks the current/pending tab URL before redirecting, and honors the exact-source native exemption. It does not read download history, other local files or native-viewer DOM.

A DNR regex capture cannot URL-encode its substitution. The final `?source=` value is therefore parsed as the complete raw suffix, preserving all original query parameters and fragments. The host runs in a tab or the original embedded slot and retrieves the PDF with the existing website session. Fetching again can fail for one-use/authenticated endpoints; POST requests are not replayed. Source validation and initialization boundaries are documented in [SECURITY.md](SECURITY.md).

Native-reader requests must come from this extension's reader host, with a browser-provided extension ID, frame ID, URL and live document ID. Central derives the URL from the sender and installs a high-priority exact-URL tab-scoped session allow rule. Top-level readers navigate the tab; embedded hosts navigate only their own frame after the successful reply. Per-frame exemption entries have separate rule IDs, with at most 64 per tab. Embedded exemptions allow only subframe/object requests initiated by the extension host, never main-frame navigation or fresh PDF requests initiated by a containing webpage. This keeps a pending cleanup from bypassing takeover on the next website navigation. Multiple embedded PDFs cannot overwrite each other's exemptions. Cleanup removes the owned IDs on containing-tab departure or closure; rollback preserves the previous frame-specific rule and state. Top-level exemptions survive PDF reloads, not tab departure/closure or browser restart. Other tabs remain unaffected. Very long unsupported regex URLs fail with guidance rather than creating a redirect loop. Local file-picker documents use a blob URL opened in a separate Chrome-reader tab while the original owner remains open.

PDF URLs remain in the reader address for reload, not in extension storage. Native exemption metadata lives in storage.session only. Local picked bytes are not persisted. Download always returns the original PDF, never the displayed dark/rotated/OCR representation.

The homepage Settings link navigates in the same tab and adds a history entry. Reader-toolbar Settings opens in the same window immediately after the source PDF tab, preserving local file-picker documents. The background derives the source tab from the extension message sender; the sandbox cannot supply an arbitrary tab target. The PDF viewport contains vertical overscroll but leaves horizontal browser navigation enabled; Alt-key history shortcuts are not consumed. History restoration recreates a disposed renderer from in-memory bytes or its validated source URL.

Settings is a single-tab surface per normal/incognito context. Each trusted top-level Settings document registers its document-start time (or BFCache return time). A small session registry of live document IDs/times survives background restarts; it stores no URLs/content and is pruned on registration. Serialized cleanup uses `runtime.getContexts()` to inspect only extension-owned documents, chooses the newest registered document regardless of load order and rechecks document identities before closing older tabs. Unregistered loading documents await their own registration so a slow newer page is not closed accidentally. No polling or new permissions are needed. Homepage-to-Settings and Settings-to-homepage navigation both remain same-tab with browser history; a PDF reader still opens its replacement Settings tab immediately on its right.

Opening a PDF prepares the sandbox toolbar independently of document transfer. The shell is revealed as soon as localization, appearance and toolbar preferences are applied. Loading animates the toolbar's bottom divider without adding a status row or changing content geometry. Document-dependent controls stay disabled until usable; theme, Settings and remote-source native fallback work during transfer. A single bounded document message follows shell initialization over its private port. The bundled parser worker starts concurrently with download; optional thumbnails wait for the first page's render. Downloads still complete and pass size/magic validation before parsing. The validated source URL enters the sandbox as inert metadata and a strictly parsed initial `#page=N` destination, with no website network capability. No renderer or OCR engine starts on the empty homepage. Parsed background documents wait for visibility without a false first-paint timeout. Failures dispose the shell/worker and expose normal recovery actions.

## Rendering and resource budgets

The extension-origin host also prevents ordinary webpage dark-mode extensions from double-applying. A `darkreader-lock` meta tag supplements this separation; Cosmic PDF does not disable or modify other extensions.

PDF input: 128 MiB, 90-second inactivity timeout renewed by incoming bytes, 30-minute total transfer budget, 30-second parse deadline outside password entry, at most 10,000 pages. Byte streaming is stopped on overflow. Images are capped by PDF.js. The original Blob remains only for native opening/download while the reader is open.

Existing annotation appearances and filled form values render into passive page and thumbnail canvases. The interactive HTML annotation/editor layers remain disabled. A toolbar control appears when markup is detected and toggles only this reader's appearance, rebuilding cached canvases and thumbnails. Native printing and downloads always use unchanged original bytes, independently of this visibility switch.

Remote retrieval can install a temporary source-origin Referer rule for the authenticated reader's exact GET URL. It is scoped to the owner tab, extension initiator, request type, and method. Session ownership is recorded before installation, checked against live document identity, and retained until successful cleanup after completion or departure. No caller-supplied header or browsing-history lookup is accepted.

Sampling choices 1×–6× change backing density, not CSS zoom. Base canvases stay within min(2 Mi pixels, sampling² Mi pixels); visible detail canvases within min(36 Mi pixels, sampling² Mi pixels), maximum dimension 8,192. The inherited reproducible PDF.js patch uses exact backing/display ratios and bounded near-viewport detail. Zoom moves in ten percentage points, wheel changes are coalesced and rasterization delayed briefly; no reparse on zoom. Custom zoom labels update immediately, but their option is located between neighboring presets only on pointer/keyboard menu opening (once per changed value). Hidden tabs do not schedule normal rendering. Thumbnails are lazy, at most 24 small canvases. Printing opens the host-owned original Blob in an adjacent Chrome-reader tab, where Chrome handles printing with the operating system. No raster print copies or plugin page-range limit are created. Default sharpening is off. Theme changes filter displayed canvases only and leave source bytes unchanged. Offscreen detail, workers, observers, and blobs have explicit cleanup.

The Preserve dark-paper colors row is hidden only when the saved Appearance is explicitly Light; Auto keeps it available regardless of the current browser theme. This changes only Settings visibility, never the stored preference or an open reader’s appearance override.

The default-on `preserveDarkPaper` switch controls a deliberately narrow black/gray-paper exception, not a semantic photo/text classifier. A 32×32 whole-page preflight rejects white and light-gray paper; only rare dark-edged candidates receive 128×128 and 257×257 whole-page confirmation. The pixel-only route requires at least 97% neutral background pixels within six luminance levels of the dark perimeter shade (below midgray), low background variance, strict per-tile limits, an entirely dark outer perimeter and at least 99.5% matching background pixels in each edge band.

Dense layouts that fail the pixel-only route can use additional evidence from the pinned PDF.js display cache. The adapter reads at most the first 48 already-rendered operators, with a maximum save depth of eight. It accepts only a neutral dark fill as the first painted object covering the whole paper, checking the actual cached path and preceding clips on a 32×32 scratch surface rather than trusting its bounding box. Missing/ambiguous cache state, earlier white paint, unsupported transforms/graphics state and non-covering paths fail closed. It never calls `getOperatorList()`, starts a second operator stream or retains the cache. Dependency upgrades must retest this private cache adapter.

With that evidence, both whole-page samples still require an uninterrupted matching dark perimeter, at least 35% matching neutral paper, low background variance and a low page mean. A per-tile white limit and bounded one-row solid-white-block scan veto light content panels even across tile boundaries; text and colored callouts near the paper edge are allowed. A white-paper margin around a dark photograph or star field always vetoes preservation. In this neutral-fill route, ambiguity, textured/colored paper beds, insufficient raster size and read/render errors retain normal inversion. Only paper shades that would become brighter at the frozen dark strength are exempt; lighter gray paper keeps normal processing. Preserving source colors avoids contrast loss from extra dimming. This favors missed exceptions over falsely exposing white paper; neither finite visual samples nor paint structure can prove document semantics.

Exported slide templates can use a dark colored/gradient image as their first full-page paint. The bounded adapter also accepts that already-decoded local/shared image when normal opaque graphics state and actual clip/transform coverage prove a complete dark paper bed. A 32-pixel spatial model must agree with the completed base page at 128 and 257 pixels, including every edge. White margins, prior paint, unsupported graphics state, and predominantly light pages reject the route. Inset light foreground content can remain on a verified dark bed when at least half of the completed page agrees with it and overall brightness stays dark. Source modeling follows the current viewport rotation and starts no decoding, parsing, or PDF rendering.

The detector reuses a completed full base canvas, never a cropped detail/thumbnail, OCR or an extra PDF render. Disabling the switch synchronizes to open readers through the private host port, removes the display exception immediately and stops analysis; enabling reuses cached verdicts without reparsing. Light mode does no image analysis; entering dark mode checks only finished cached page views. Each page is decided at most once per reader, including failures; zoom/rotation and matching thumbnails reuse the result. The cache is one byte per page (at most 10,000 bytes), with a single reusable scratch canvas no larger than 257×257, zeroed after each decision. Unknown dark canvases remain concealed until their completed render can be checked before paint; known pages retain progressive rendering. No whole-document scan, timer or persistent content cache is introduced. Paper boundaries, text selection, OCR, printing and downloaded bytes are unchanged.

Document properties are imported and read only on toolbar request, with one cached metadata read per open reader. Values are bounded plain text; the original file URL appears directly below File name when available, never as an active link. No metadata HTML, URL or script executes. File size uses received bytes and decimal units. Page dimensions include the original PDF page rotation and UserUnit, not the temporary viewing rotation. Date formatting preserves each source wall time and explicit UTC offset (without pretending a missing offset is known). Whole-hour offsets use compact notation such as `UTC+8`; nonzero minutes remain, such as `UTC+5:30`. Seconds are shown only when present in the PDF date, including zero seconds. Locale-based defaults retain the English medium date/short time convention, with spaced Chinese year/month/day; numeric date-order formats are selectable. Metadata is never reread for language/format changes. The modal keeps its established dimensions and closes on an outside press/click, not on a drag that starts inside it.

The `useChromeFind` switch defaults on, preserving native Chrome keyboard behavior: ⌘F/Ctrl+F are neither cancelled nor simulated. The toolbar/More actions Find button always opens PDF.js whole-document search, regardless of this setting. Turning the switch off also routes the shortcuts to built-in search. The preference updates live without dismissing an already-open reader search. Search matches use orange overlays, with a stronger current match in both themes; forced-colors palettes remain native. No shortcut banner or simulated browser command is used. Chrome only searches text currently present in the DOM (including completed OCR overlays); the extension does not force all pages into memory to expand its reach.

## OCR

Settings and the reader share allowlisted language checkboxes. At least one language remains selected; any combination of English, Simplified Chinese and Traditional Chinese is supported. English and Simplified Chinese are selected by default. Only selected models are initialized. Defaults apply to newly opened readers; per-document choices do not rewrite the saved defaults.

Tesseract runs after a user recognition action, or on a stable current page with an empty successfully rendered native text layer when either the independent `automaticOcr` preference is on or AI explanations are enabled/usable. `automaticOcr` defaults off and updates open readers immediately; it works without an AI account or key and never enables the AI selection button or AI requests. The latter is coordinated by `automatic-ocr.js`: rendering/page/readiness/visibility events feed one 500ms debounce; it never scans the whole document, polls, or interrupts manual work. Empty/error/cancel outcomes are not automatically retried; explicit recognition remains the retry path. Successful results are reused and may be rebuilt only after normal memory-budget eviction when the page is revisited. Explicit Clear does not immediately regenerate cleared results. Removing the last automatic trigger cancels an unfinished automatic job, not a manual job; disabling AI alone leaves independent automatic OCR available; a manual action can take ownership of an active automatic job. Hidden pages do not start another job. The toolbar defaults to recognizing the current page; `next5`/`next10` mean current plus exactly five/ten following pages, clipped at EOF. A 550ms hold opens the side panel without a duplicate click, including when the button is in More actions. The alternative panel behavior opens it on a normal click. Closing the panel never cancels an active run; both panel and compact feedback offer explicit cancellation. Each run handles a selected range of at most 20 pages sequentially using one LSTM worker, terminated after completion, error, cancellation or reader closure. Worker ownership starts before model loading, so Cancel is effective during initialization too. Each stage/page has a 120-second deadline. English, Simplified Chinese and Traditional Chinese models and both SIMD/non-SIMD LSTM cores are local; no cache/CDN/telemetry is used.

OCR rasterization uses the original light PDF page, independent of display sampling, with a 4 Mi pixel/4,096-axis limit. Temporary canvases are zeroed after encoding. Lightweight results are bounded to 20 pages, 50,000 word rectangles and 500,000 text characters. Word rectangles are validated and stored in PDF coordinates, enabling selectable overlays to follow zoom and rotation without rerunning recognition. Each completed page is overlaid immediately; no separate transcript is kept or shown. Line boundaries and English word spacing are preserved without inserting spaces between recognized Han glyphs. A user recognition request gives the new OCR text priority for the entire recognized page, without a text-quality heuristic or separate preference. A nonempty overlay is published atomically and removes the native text layer from rendered layout with `display: none`, excluding it and its descendants from Chrome Find and selection even if PDF.js later recreates the layer. Empty or whitespace-only results do not suppress native text. Clearing results, cache eviction and disposal restore the original layer; other pages remain unchanged. Cancellation or failure before publication preserves the existing layer. The original PDF is not modified; OCR does not export a searchable PDF. The engine's worker protocol is pinned and tested; upgrades must retest initialization, recognition and cancellation.

## Repository and release standards

English/Simplified Chinese README and changelog have equivalent structure. README introduces capabilities, not a catalog of implementation rules. Technical details live here; repeatable validation lives in QA.md. System `.DS_Store`/AppleDouble files are ignored by Git and validation. Dependencies are vendored, pinned, licensed and reproducible; no runtime remote code. Release sources and downloads are maintained in the Cosmic PDF repository.

## Interface design

The appearance button retains single-click switching. Its right-click/keyboard menu offers reader-local Auto, Light and Dark overrides without changing saved defaults. Auto explicitly follows device changes even if the frozen default was Light or Dark. A fixed-mode private-port message accepts only auto/light/dark; invalid choices are ignored. The three neutral menu rows are built on demand, light-dismiss and support Escape/arrow keys. No document reload, polling or extra permission is involved.

Use the Cosmic Gemini family palette, flat outlined icons, compact identity header and rounded cards. Settings labels/controls and OCR choices are 15px; supporting text is at least 14px, except the opening-screen copyright at 13px and brief AI accuracy reminder at 12px. Preserve contrast in both themes and reflow at narrow widths rather than shrinking type. The editable brand is `extension/icons/icon.svg`; regenerate manifest PNGs with `scripts/render-icons.mjs` using `PDF_PLAYWRIGHT`/`PDF_CHROME`. Generation also fingerprints all first-party HTML favicon/brand URLs from the SVG content and records source/raster hashes in `extension/icons/integrity.json`. This changes the favicon cache key only when the artwork changes, without runtime work. `scripts/check.mjs` rejects stale source/raster hashes, incorrect PNG dimensions, missing favicons and old HTML icon references. Settings displays the version from `chrome.runtime.getManifest()`, never a hardcoded release number.

Two independent toolbar-content checkboxes allow both items, branding only, filename only, or neither. Filename defaults to visible and branding to hidden; existing explicit choices remain unchanged. Selecting both retains the two-row layout. Hiding either item uses a single row when space permits. The appearance button always precedes Print. Pages stays at the leading edge unless explicitly moved into the menu: on the second row when both identity items are shown, otherwise in the first-row leading cluster. Branding-only or filename-only content is left-aligned after Pages with a 12px gap, before the centered tools. Filename-only mode is left aligned, bounded to 320px or available space, and ellipsized with the full name in its tooltip. Narrow windows reflow controls without reducing text or button spacing. Current and total page counts use identical centered widths based on the total page count; the slash is a separate separator.

Toolbar action visibility is an allowlisted map of explicit overrides. Find, Previous/next page, Fit width/page, Print, Document properties and Use Chrome reader default to More actions in all four identity modes; explicit choices override these defaults independently of layout. The native-reader menu label is shortened to Chrome reader. The filename is also a keyboard-accessible properties button: disabled until parsing completes, it shares the same lazy dialog and cached metadata as the properties action. The dialog is capped at 560px in width and height within the viewport, with unchanged 15px body text. It autofocuses its heading and resets scroll offsets only on opening, never shifting an already-open dialog during locale updates. No hidden actions means the Settings button navigates directly; otherwise it opens an on-demand icon-labeled menu plus Settings. Menu commands delegate to the original controls and their disabled state; no new privileged bridge commands are introduced. A hidden fit selector is replaced with a 66px percentage input accepting optional `%`, clamped to the existing 25–500% range. Open menus support keyboard navigation, Escape, outside dismissal and a second trigger click. Trigger pointerdown records whether the auto popover was open, preventing light-dismiss-before-click from reopening it; keyboard clicks use the current state. Their intrinsic width follows the longest current localized caption, bounded by available viewport space; no continuous measurement is needed. Settings labels mark factory-default hidden actions, independently of current overrides.

Compact wrapping uses the intrinsic widths of visible toolbar groups and side actions, not a fixed viewport breakpoint. Side tracks balance the reading controls where possible, while filename-only mode reserves a 96px minimum before ellipsis. A toolbar-only ResizeObserver batches geometry reads into animation frames and disconnects on disposal; it never scans document pages or runs on PDF scrolling. Settings changes measure once before presentation, and later resizes, font geometry and page-count widths trigger remeasurement. The full filename-and-branding layout keeps its two rows, with an extra narrow-window row only when necessary to avoid overlap.

Visible-page rendering progress reuses the rendering queue’s existing visible-page set. A single cancellable 200 ms delay drives the existing toolbar-divider line; cached/fast pages and background prefetch cause no indicator. Page-interior PDF.js loading pseudo-elements are suppressed without changing rendering priority, allocations or document layout. Visibility/disposal clears pending feedback.

## External Links Capture

When document links are enabled, an explicit annotation or outline link click lazily loads a compact capture dialog inside the existing PDF sandbox. Internal PDF destinations remain internal. The separate default-on captureLinks preference updates open readers immediately; disabling it dismisses an open web prompt and restores direct safe web-link opening, without weakening the document-links gate. Until a permitted Open choice, middle/modifier clicks also enter capture. Web annotation anchors carry no external navigation target while capture is on; protocol annotations never carry one. No telephone-location dataset, page observer, or persistent link state is added. Closing or disposing removes the transient content. Interface language and reader theme apply to the prompt. Target validation, copy-only protocols, and application confirmation rules are maintained in [SECURITY.md](SECURITY.md).

The opaque reader uses `worker.js` to adapt the pinned, self-contained PDF.js worker module into a classic blob worker: remove its checked export footer and resolve `import.meta.url` to the fixed packaged asset. This avoids Chrome’s opaque-origin module-worker redirect failure. The adapter waits for the native ready message, passes its port to PDFWorker, and explicitly owns termination/blob disposal on failure, abort and normal teardown; it never falls back to a main-thread fake worker. Startup has a bounded deadline. Dependency upgrades must revalidate the adapter and real-worker browser assertion.

The fixed reader iframe delegates only the `clipboard-write` Permissions Policy feature (opaque origin requires `*`); clipboard read remains disabled and no clipboard permission is added to the extension manifest. PDF.js whole-document Copy and link-copy fallbacks stay local, without sending document text through the privileged bridge. Dialog opening temporarily makes the dialog inert during native initial-focus selection, restores it synchronously and explicitly focuses the heading/input/button without scrolling. Native modal isolation, Escape and return focus remain intact; no cross-origin `autofocus` attributes are used.

Both pinned Tesseract core glue files decode embedded base64 WASM using their existing local byte decoder before any fetch/XHR branch. The guarded `vendor-ocr.py` patch is documented and integrity-pinned; model/WASM bytes, error reporting and local-only CSP are unchanged. Recognition diagnostics such as detected diacritics are informational, not failed OCR.

Settings puts the product name above the localized Settings subtitle. More actions choices reuse reader glyphs as decorative icons, with default-hidden annotations in the standard muted color and unchanged accessible checkbox labels.

The internal capability is named External Links Capture. Its pure protocol parser, target policy, and sandbox-local modal live under `shared/external-links-capture/`, shared in implementation with Cosmic Gemini. Mailto Capture uses the same classic-compatible parser without importing the viewer UI or changing its website settings.

### OCR selection geometry

Recognized words retain engine block/paragraph/line reading order, with left-to-right ordering inside each horizontal line. Each cached word carries its row identity and PDF-space corners. The selectable overlay uses inline word slots in each row within one shared rotated coordinate system, shared vertical bounds, and explicit line breaks, instead of unrelated absolute word boxes. Slots cover interword gaps; transparent glyphs retain individual horizontal scaling. Zoom and rotation rebuild only the bounded overlay from cached coordinates, never OCR. Repeated page-render events with the same result and viewport geometry preserve the existing DOM and active selection. No pointer-move selection handlers, content scans, or new settings are added.


## Settings and interaction lifecycle

Settings writes are serialized and applied to a fresh normalized base. Pending edits remain visible across locale-driven DOM rebuilds and incoming storage events. A delayed save callback must not republish a stale snapshot; post-write readback and an observation revision protect the latest received state. Failed writes remove only their own pending edit and do not poison later writes. Ordinary updates preserve control focus. Only automatic-opening changes reconcile takeover rules; cosmetic settings do not rewrite network rules.

Native-reader handover validates the sender's current document ID before installing its tab/source exception and again before navigation. Cleanup ownership is persisted first. Installation/navigation failures roll back previous rules and metadata; failed rollback retains ownership for cleanup. Closing a tab also removes a deterministic orphan exception if its metadata is absent.

Reopened native dialogs reset their return value so Escape cannot repeat a previous Print/Open action. Modal keyboard events cannot navigate the underlying PDF. Page-number inputs accept whole page numbers and preserve the current page on invalid input.

## AI explanations

Press 1 outside editable controls and custom pickers in Settings to toggle Test mode at the end of the API service picker. Toggle/selection use authenticated Settings-only commands and a separate pair of booleans in chrome.storage.local, not provider preferences, document/history storage or the credential vault. The mode persists across Settings closure, refresh and browser restart until 1 turns it off; switching it off removes the option, clears its selection and cancels local work. The saved real provider and all keys remain unchanged. The Settings footer appends (Test mode) to the actual manifest version while unlocked, even when a real model is selected. Reader hosts refresh public status on local test-state changes. Selected test requests branch before vault reads/API transport and generate local samples through the normal bounded, cancellable stream path (the background module is statically imported for Chrome service-worker compatibility). They still require an explicit Explain/follow-up action and enabled API mode. Private windows cannot enable or reuse the testing state. First replies demonstrate text/emphasis/lists/quotes; follow-ups cycle different local examples. Only follow-up question keywords code/代码 or table/表格 add code or table samples, independently, case-insensitively. Selecting a real model exits the test selection without running a request. No network fallback is allowed if the selected test path fails.

`core/ai.js` holds public provider configuration, limits and prompt construction. Customs Province routes AI work to `background/products/ai-explanation.js`; Central only authenticates/routes fixed commands and notifies preference changes. Provider calls live in `ai-client.js`, while `ai-vault.js` owns credentials. The trusted reader host bridges normalized requests through a dedicated runtime Port; the opaque renderer receives public status and answer text, never a credential or arbitrary network capability. AI is off by default; Gemini is the initial provider, explanation language follows the interface, and nearby context defaults on. Explicitly saved context preferences are preserved; no migration overrides them. The neutral Satellites-style sparkle switch sits immediately left of appearance. Its slash/dim state signals Off. AI preferences synchronize live without restarting PDF parsing or OCR. The API panel omits the selected-passage heading/preview and repeated Gemini plan notice; its short accuracy reminder uses 12px with 1.35 line height, while answer text stays 15px. The compact context controls use 14px labels, 1.3 line height and 6px gaps above the controls and before the model/status row. The model stays left and the status, shortened to Complete/完成 on success, aligns right; the same live region and Stop action are retained, and long statuses can wrap without horizontal overflow. The captured selection/context remains intact for API requests and follow-ups. Each API turn positions the conversation scroll container once, at the first answer or the new follow-up question. CSS gives only the latest turn a viewport-height minimum so short replies still align; previous turns keep natural height. Streaming and completion never force scrolling, and native scroll anchoring is disabled on the conversation container. No observers, scroll polling or permanent sticky question are added. Website-mode long-question handoff retains its source preview.

Initial model IDs remain: `gemini-3.5-flash-lite`, `gpt-6-luna`, and `claude-haiku-5-5`. The connection-test button sends one manual, non-streaming JSON generation request to the selected model, with a 32-token output budget for the initial models and 1,024 tokens for other models. Gemini uses :generateContent; OpenAI/Claude set stream:false. It includes no document text, costs follow the API's rules, and saving a key makes no provider request. A successful returned text is required; the test does not depend on SSE completion or an exact literal OK. Provider API quotas, fees, and data policies apply, including Gemini free-tier distinctions. Transport and credential policies are maintained in [SECURITY.md](SECURITY.md).

Settings lists saved keys by service without displaying or refilling their values. A separate Add/Replace editor holds only a transient password draft; cancellation, method changes, and page departure clear it. Each row has Test/Stop, Replace, and confirmed Delete; its result describes the service response at test time and stays local to that Settings instance. The selected answer model is independent of the key editor's service. There is no bulk-delete UI. Replacing/deleting a key cancels active work for that service. Reset settings resets preferences but does not delete credentials. Vault encryption, caller authorization, and private-browsing policy are documented in [SECURITY.md](SECURITY.md).

Selected native/OCR text must originate in visible PDF text layers, respect PDF copy permissions and stay within 8,000 characters. Selection uses the browser's visible-text representation rather than Range.toString, which can include suppressed native layers between OCR pages. Context captures at most 1,500 characters on each side of the selected range from its active layers and is sent only while Include nearby paragraphs is enabled; OCR rows retain line boundaries and never mix in native text from the same page. Other unrecognized pages retain their original text. The background also strips context when its trusted preference is off. No automatic full-document extraction, upload, filename/source-URL field or whole-document OCR/page scan is added. Empty current pages use the bounded local automatic OCR described above. API conversation state is scoped to one passage in one reader and discarded at disposal. Follow-ups retain at most ten alternating prior messages and 16,000 characters; questions cap at 1,500 characters.

`selection.js` clears only PDF reading ranges on primary clicks, window focus loss (including still-visible split panes) and tab hiding. Explain with AI preserves the current selection until it captures a private text/context snapshot; focus loss after handoff clears highlighting without losing the question or cancelling work. Right-click Copy and Shift-click extension remain native. AI-reply and form-field selections are untouched. Host blur forwards only a clear-selection signal over the private channel, never text. No tab monitoring, polling or extra permission is introduced, and listeners retire with the reader lifetime.

The shared explanation goal is understanding selected text, not summarizing a PDF passage. A word/name/abbreviation, longer selection, code or equation may call for different depth and structure; the model can use relevant background, examples, analogies and connections without a fixed answer sequence. Missing context does not require refusing a standalone term: the prompt requests a useful explanation and an explicit interpretation or alternatives where ambiguity matters. It does not name the file format or imply access to the full document. Supplied content stays distinct from background knowledge; unsupported author intent, fabricated citations and silently repaired OCR are discouraged. API replies support common Markdown through the locally pinned Marked 18.1.1 lexer, lazy-loaded only for an explicit API answer. The passive output policy is defined in [SECURITY.md](SECURITY.md). Formatting visits at most 4,096 tokens with a maximum nesting depth of 32. Ordered list markers remain at the content edge without extra indentation. Only assistant answers are formatted; questions and conversation history retain their original source. Streaming formatting is coalesced to an animation frame and reuses unchanged DOM nodes; completion, Stop and error flush pending text without forcing scroll. Lexer/conversion errors or complexity limits fall back to literal text. Website replies may use the website’s formatting. These choices follow the task/context separation described in [OpenAI’s prompt guide](https://developers.openai.com/api/docs/guides/prompt-engineering), [ChatGPT’s prompting guide](https://developers.openai.com/cookbook/examples/chatgpt/chatgpt_prompt_guide/chatgpt_prompt_guide) and [Claude’s prompting guidance](https://platform.claude.com/docs/en/build-with-claude/prompt-engineering/claude-prompting-best-practices). Prompt construction checks cover payload structure; use the review cases in [QA.md](QA.md) to assess explanation quality.

SSE decoding preserves chunked UTF-8/CRLF and accepts only text deltas, skipping reasoning. Output caps at 16,000 characters, events at 64,000 characters and the response stream at 512,000 bytes. Errors become fixed localized codes, never raw provider bodies. Bounded error JSON (16 KiB) is examined locally for structured status/type/code/ErrorInfo reasons: Gemini 400 API_KEY_INVALID is authentication, FAILED_PRECONDITION is project/account setup, SERVICE_DISABLED is an API setup issue, 403 is access restrictions, 404 is model availability, 429 is quota, 400/422 is request configuration and 5xx is a service failure. Fetch rejection is network and malformed/truncated responses are incomplete, not claims that an otherwise valid key is wrong. Connection JSON is bounded to 64 KiB. Unknown/raw messages, request IDs, credentials and arbitrary metadata are never sent to UI/logs. Explanation jobs have a 25-second first-text/idle budget and 90-second overall deadline; connection tests have 25 seconds and report deadline expiry as timeout, not user cancellation. Only one test per Settings tab may remain active; Stop is authenticated/scoped to that tab and provider. A heartbeat exists only during active user work. Stop, switch-off, key deletion, replacement selection, tab navigation and renderer disposal abort work; obsolete IDs/ports cannot repaint a newer explanation. Visible work shares the toolbar-divider progress line. There is no background polling or persistent text history.

The error categories follow [Gemini troubleshooting](https://ai.google.dev/gemini-api/docs/troubleshooting), [OpenAI API errors](https://developers.openai.com/api/docs/guides/error-codes) and [Claude API errors](https://platform.claude.com/docs/en/api/errors). Gemini keys can be subject to project/service and application restrictions, as described in [Google’s key guide](https://ai.google.dev/gemini-api/docs/api-key). An invalid dummy-key endpoint check proves reachability and error mapping only; it does not verify any user’s valid key, project billing or model access. Requests use the saved per-service model and never fall back to a different model automatically.

Gemini defaults to [`gemini-3.5-flash-lite`](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash-lite) model for explanations and connection tests. GenerateContent requests set `thinkingConfig.thinkingLevel` to `minimal`, not the older Gemini 2.5 `thinkingBudget`; minimal reasoning does not guarantee thinking is disabled. See [Google’s GenerateContent thinking guide](https://ai.google.dev/gemini-api/docs/generate-content/thinking). The provider storage identifier remains `gemini`, preserving saved encrypted keys.

### API model selection

Settings separates API service and model. `aiModels` stores one validated ID per service; missing values retain the initial defaults. Both serialized preference writers merge per-service edits, and new explanation/connection-test requests read that saved model. Existing streams retain their initial request snapshot. Model IDs cannot change hosts or endpoint paths; Gemini IDs are encoded into the fixed GenerateContent path, while OpenAI/Claude IDs remain JSON data. The initial models retain their existing tuning; other models use the provider's standard generation defaults instead of inheriting model-specific reasoning parameters.

An explicit Get latest models action uses the encrypted saved key in the background, without document text or token generation. It calls the official [Gemini Models API](https://ai.google.dev/api/models), [OpenAI Models API](https://developers.openai.com/api/reference/resources/models/methods/list), or [Claude Models API](https://platform.claude.com/docs/en/api/models/list). Only Settings can fetch/cancel lists. Requests omit cookies/referrers, reject redirects, and are bounded to 30 seconds, ten pages, 1,000 records, and 1 MiB per response. Gemini page tokens and Claude after_id cursors preserve response order; OpenAI's list is read in its returned order. Duplicate/invalid IDs are removed without sorting, and retired entries are omitted when explicitly identified by the service. A shared media-generator filter excludes dedicated image/video model families from both fetched and cached catalogs while retaining ordinary multimodal text models. A previously selected excluded model keeps its existing control label but is absent from the menu; no replacement model is chosen. Request validation prevents use of excluded models.

The bounded local catalog stores only model IDs, labels, and fetch time. Serialized writes preserve other services' catalogs. Replacing/deleting a key clears its catalog, and cancellation/failure leaves the prior successful list and selected model unchanged. Successful fetching automatically opens the complete returned menu in vendor order. Flash-Lite/Luna/Haiku families receive a localized parenthetical recommendation; they are not ranked or selected automatically. If no family matches, the user chooses. A saved model absent from the response remains a separately marked current selection after the returned list. Labels are passive text, not HTML. No catalog request runs on a timer or simply from opening a PDF.

All Settings selects share `settings/dropdowns.js`: a themed DOM listbox and button-based select-only combobox retain the underlying select/value/change preference contract. Pickers support arrows, Home/End, Enter/Space, typeahead, Tab, Escape, outside dismissal, disabled state, and localized accessible labels. Menus align with their control, flip within the viewport, and are destroyed on close; option DOM is built only while open. Ordinary preference updates reuse widgets and preserve focus. No operating-system popup, polling, or framework is required.

### AI website handoff

Settings presents radio choices in this order: Built-in AI via API, then Bring Your Own AI via Subscription. The macOS-style circles retain native input semantics, keyboard navigation and visible focus; forced-colors mode uses browser rendering. `aiMode` defaults to `subscription`, without a default suffix on either label; explicit saved choices are preserved. `aiWebsite` independently selects ChatGPT or Claude, defaulting to ChatGPT. Service choices likewise have no default suffixes. Both modes share aiEnabled, explanation language, optional nearby context and the neutral sparkle/selection entry. Switching methods cancels obsolete work and clears the reader's local passage conversation; switching back preserves encrypted keys and API model choices. The API product rejects subscription-mode requests before reading a key or making a provider call.

Customs Province owns `ai-website.js`. The fixed handoff destinations are `https://chatgpt.com/?q=...` and `https://claude.ai/new?q=...`. `core/ai-web.js` builds a single user-voiced question from the shared explanation builder and bounded JSON-quoted document data: “I selected the text below while reading. Please help me understand it…”. The builder handles transport-specific wording directly, without rewriting an API system prompt through string replacement. An encoded URL budget of 12,000 characters is a conservative extension policy, not a website limit: over-budget questions remain complete in a sandbox-local Copy question/Open AI website panel. No partial question is sent; the separate Open choice omits q and the user pastes the question manually. Copy uses the existing write-only sandbox policy and never sends a clipboard command through the host. Neither website's Submit button is clicked; prefill/automatic submission behavior is owned by that website.

Website mode uses the browser's ordinary logged-in page, including free or subscribed accounts. It does not require or verify a paid subscription, inspect cookies/credentials, inject a content script, read answers, operate model selectors or return website replies into Cosmic PDF. No iframe embedding, proxy or removal of website security headers is used.

The trusted host routes bounded AI_OPEN_WEBSITE/AI_CANCEL_WEBSITE requests. The background derives the owner tab from the sender, validates the extension ID, nonnegative frame ID and exact reader path, then rechecks the current document ID/URL through runtime.getContexts before navigation. Public methods never accept an arbitrary destination or tab ID. Global serialization prevents rapid opens from creating competing companions. Preference changes, cancellation and source departure retire pending jobs. An already opened conversation is not automatically closed when its PDF closes or when AI is disabled.

Only the source-reader tab ID and owned companion-tab ID live in a bounded storage.session registry (128 entries); it survives worker suspension, not browser exit. The registry is cached after one lazy read and written only when ownership changes. It contains no document/question URL, filename, text or account data. Reuse requires a still-live companion in the same window/privacy context and one of the exact supported website origins. Closed, repurposed, moved or unrelated-split tabs are left alone and replaced. Source departure/closure and companion departure/closure retire registry entries. Reuse navigates the companion to a new question, so it can leave a previous conversation or replace an unsent draft; this is described in Settings.

Feature detection uses tabs.createSplit where exposed (officially Chrome 155+), with matching pinned/group state, adjacency and no unrelated existing split. An already paired PDF/AI split is retained. Unavailable/rejected automatic splits leave a functioning neighboring tab without a duplicate window/tab or warning. No split-width API is exposed, so the extension does not claim a 70:30 ratio or simulate browser UI controls. [Chrome Tabs API](https://developer.chrome.com/docs/extensions/reference/api/tabs#method-createSplit) documents the boundary. No new extension permission is needed. Website-mode prefill text necessarily enters an AI website URL and can appear in history/sync or website retention; unlike API mode, conversation lifetime is controlled by that website.

## Direct download publishing

`python3 scripts/build-downloads.py` builds deterministic installation and full-source ZIPs from the current tracked working-tree files. Stage new source files before building. Fixed timestamps and regular-file permissions keep archives reproducible. The installation archive includes only `extension/`; the source archive includes tracked project sources except generated downloads, local/ignored folders and personal helpers. Git metadata, ignored files, and local configuration are excluded from both archives. No downloaded package recursively includes generated ZIPs. SHA-256 metadata is written next to the files.

Commit/push `downloads/` with each release. The existing main-root Pages site at `cpdf.songming.org` serves the ZIPs directly. There is no GitHub Actions workflow, token requirement, redirect to a GitHub download host or website-side build step. The marketing site is maintained separately at `pdf.songming.org`.

## Reader lifecycle safeguards

Page navigation handles only unmodified arrow/Home/End keys outside editable controls; modified selection/navigation combinations and IME composition remain native. The host backdrop and color scheme follow every appearance change, including the period before the child shell is ready. Retired private-channel handlers, password prompts/confirmations, parser deadlines, and lazy properties creation ignore delayed callbacks.

Thumbnail generations are invalidated by sidebar/tab closure, document visibility changes, and rotation. Each asynchronous page lookup/render rechecks visibility and ownership before allocating or publishing a canvas; rejected/cancelled scratch canvases are zeroed. Print requests are ignored after renderer disposal; the host revalidates document ownership before opening its original Blob.

### Directional page preparation

The existing PDF.js sequential queue prepares four base pages in the scrolling direction and two behind, after visible rendering work. Its minimum cache is eight pages, with a two-Mi-pixel budget per base canvas rather than four; selected visible-detail sampling and its larger budget stay unchanged. High-resolution detail waits for the renderer’s 100 ms scrolling pause, so movement favors ready base pages and stationary reading regains full detail. Preparation checks only a bounded neighborhood, never the whole document, and adds no worker, polling loop, network request, or persistent cache.
